# 데이터 계약과 해석 한계

## 현재 스냅샷

아래 수치는 문서 작성 시 `data/artifacts.js`를 로컬에서 읽어 새로 집계한 값이다.
공식 사이트를 재수집하거나 현재 원문·이미지의 유효성을 확인한 결과는 아니다.

| 항목 | 로컬 집계 |
| --- | --- |
| 전체 / 고유 ID | 1,125건 / 1,125개 |
| 한국 / 중국 | 1,068건 / 57건 |
| 소장처 ID | `nmk` 1,068건, `gugong-bj` 57건 (`vam`, `met`은 등록만 되어 있고 아직 유물 없음) |
| 분류 | `ceramic` 1,079건, `painting` 43건, `metalcraft` 3건 |
| 연대 근거 `dateBasis` | `object-record` 23건(한국), `assigned-comparison` 1,045건(한국), `dynasty` 57건(중국) |
| 유약 `ware` | `celadon` 1,077건(한국 1,068, 중국 9), `null` 48건(중국 회화 43·금속 3·균요 2) |
| 위치 확실성 | 전부 `capital-fallback` |
| `holdingMuseumVerified` | 전부 `true` |
| 연대 필터 | 전부 12세기와 겹치며 다른 세기와는 겹치지 않음 |

`index.html`의 영어 About 문구는 이 표와 아래 연대·위치 설명을 요약한 정적 텍스트다. 데이터 변경 시 함께 갱신한다.
이는 선택된 수집 결과의 크기다. 박물관의 전체 소장 수나 최대 수집량이 아니다.
한국·중국 간 건수 차이도 역사적 생산량이나 소장품 규모 비교의 근거가 아니다.

## 유물 스키마

파일은 JSON API가 아니라 `window.ARTIFACTS = [...];` 형태의 JavaScript다.
아래는 현재 앱과 수집기가 공유하는 전체 필드 계약이다.
오프라인 검사에서 문자열은 `nameHanja`를 제외하고 공백만 있거나 비어 있으면 안 된다.

| 키 | 형식·허용 값과 의미 |
| --- | --- |
| `id` | 비어 있지 않은 고유 문자열; 현재 `kr-nmk-*`, `cn-gugong-*` |
| `name` | 비어 있지 않은 표시 이름 |
| `nameHanja` | 한자명 문자열; 확인되지 않으면 빈 문자열 허용 |
| `holdingMuseumId` | `MUSEUMS.id` 참조; 현재 `nmk`, `gugong-bj` |
| `holdingMuseumVerified` | 불리언; 아래의 제한된 의미에 유의 |
| `cultureRegion` | 열거형 `KR`, `CN`; 유물의 문화권. 소장처 국가와 별개(V&A·Met은 KR·CN 유물을 소장) |
| `yearStart` | 정수, 필터용 시작 연도 |
| `yearEnd` | 정수, 필터용 끝 연도; `yearStart <= yearEnd` |
| `dateLabel` | 사람이 읽는 연대 표제; 원문을 그대로 옮긴 값이라고 보장하지 않음 |
| `dateBasis` | 열거형 `object-record`(개별 기록에 연대 표기), `dynasty`(왕조·시대 범위에서 추정), `assigned-comparison`(연대 미상을 비교용으로 배치) |
| `dynasty` | 왕조명 문자열; 현재 `고려`, `북송`, `남송`, `송` |
| `dynastyHanja` | 비어 있지 않은 왕조 한자명 문자열; 현재 필수 |
| `category` | 열거형 `metalcraft`, `ceramic`, `painting` |
| `ware` | 열거형 `celadon`, `white`, `blue-and-white` 또는 `null`; `ceramic`만 값 가능. 이름·재질에 청자/靑磁/青瓷/青釉가 명시된 경우만 `celadon`, 나머지는 `null`(미분류) |
| `material` | 재질 문자열; 수집기의 정규화·추정이 포함됨 |
| `origin` | 아래 네 키를 갖는 위치 객체 |
| `origin.lat` | 숫자 위도 -90~90; `unknown`이면 `null` |
| `origin.lng` | 숫자 경도 -180~180; `unknown`이면 `null` |
| `origin.place` | 위치 설명 문자열; 추정이라는 사실도 명시 |
| `origin.certainty` | 열거형 `known`, `capital-fallback`, `unknown` |
| `image` | 자격 증명 없는 절대 HTTPS URL; 외부 이미지 CDN 허용 |
| `imageLicense` | 권리 관련 설명 문자열; 자유 텍스트이며 허가 증명 아님 |
| `imageCredit` | 이미지 제공처·출처 표시 문자열 |
| `source` | 자격 증명 없는 절대 HTTPS URL; `museum.go.kr`, `dpm.org.cn`, `vam.ac.uk`, `metmuseum.org` 또는 각 하위 도메인 |
| `description` | 설명 문자열; 현재 수집기가 만든 문장 포함 |

`known`은 개별 유물의 위치 근거가 있을 때만, `unknown`은 근거가 없을 때 사용한다.
현재 검사는 `holdingMuseumId` 참조를 요구한다. 박물관 `country`와 유물 `cultureRegion`의 일치는 요구하지 않는다(해외 소장 유물).
`capital-fallback`은 역사적으로 붙인 키 이름이며 수도만 뜻하지는 않는다.
현재 강진 가마터와 중국 동부 대체점도 이 값에 포함된다.
알 수 없는 위치를 임의의 도시나 숫자 0으로 채우지 말고 `unknown`·`null`로 남긴다.
화면은 이 계약을 자동 강제하지 않으므로 데이터 수정 후 오프라인 검사가 필요하다.

## 보조 데이터

`window.MUSEUMS`의 전체 키는 `id`, `name`, `nameHanja`, `country`, `city`, `lat`, `lng`, `color`다.
`country`는 소장처 국가 `KR`·`CN`·`GB`·`US`이고, 해외 기관의 `nameHanja`에는 원어 공식 명칭을 넣는다. 위·경도는 박물관 위치이며 유물 제작·출토 좌표가 아니다.
`window.PERIODS`는 5~19의 세기 키마다 `cn`, `kr` 문자열을 갖는 시대 표제 사전이다.
표제는 탐색 보조 정보이며 개별 유물의 편년이나 왕조 경계를 입증하지 않는다.
`window.EARTH_TEXTURE`는 현재 `img/earth-blue-marble.jpg` 경로 문자열이다.

## 연대의 근거 수준

한국 23건은 현재 `dateLabel`에 12세기가 들어간다.
전반 13건, 세기 전체 8건, 중엽 1건, 후반 1건이다.
수집기는 공식 상세 HTML 전체에 있는 `12세기` 문자열을 탐지한다.
이는 개별 편년 필드를 엄밀히 판독하거나 연구자가 재검증했다는 뜻이 아니다.
전반 1101~1150, 중엽 1135~1165, 후반 1151~1200도 앱의 정규화 규칙이다.

나머지 한국 **1,045건**은 `고려, 공식 상세 세기 미상`으로 표시된다.
이들에게 부여한 1101~1200은 **비교 화면에 넣기 위한 인위적 범위**다.
고려 청자라는 사실만으로 실제 제작 시점을 12세기로 확정할 수 없다.
필터에 나타나는 것과 해당 세기로 편년되었다는 주장은 구분해야 한다.

중국은 북송 23건 1101~1127, 남송 17건 1127~1200, 송 17건 1101~1200이다.
이 범위는 목록의 시대·제목에서 왕조를 추정해 12세기로 잘라 붙인 값이다.
중국 57건의 개별 제작 연대를 확인한 결과가 아니며 일부는 12세기 밖일 수 있다.

## 위치·소장처·이미지

현재 위치는 강진 1,068건, 카이펑 23건, 항저우 17건, 상하이 대체점 17건이다.
모두 공통 대체 좌표이며 이 스냅샷에는 개별 출토지·제작지의 증거가 연결되어 있지 않다.
`app.js`의 나선형 표시 좌표는 이 대체점을 더 펼친 것으로 지리 근거가 아니다.
`holdingMuseumVerified: true`는 공식 사이트 목록 소속을 근거로 수집기가 설정한다.
독립적인 소장 이력, 취득 경위, 현재 소장 상태의 조사·감정을 뜻하지 않는다.

한국의 `KOGL Type 1`은 수집기가 일괄 입력한 문구다.
중국의 `공식 이미지 URL`은 주소 출처 설명이며 이용허락 유형이 아니다.
둘 다 개별 이미지의 권리·제3자 권리·재배포 조건을 감사한 결과가 아니다.
공개 저장소에 URL을 싣는 것과 원본 이미지를 재배포할 권리는 별개다.
권리 검토 없이 이 필드만으로 다운로드·복제·상업적 사용을 허용하지 않는다.
`img/`의 과거 유물 사진은 현재 데이터가 사용하지 않는 스냅샷이며 삭제하지 않는다.

## 백자·청화백자 표본 수집기

`scripts/collect-porcelain-sample.mjs`는 조선 백자·청화백자와 명·청 백자·청화 자기 후보를 모으는 별도 도구다.
결과는 검토 파일(기본 `review/porcelain-candidates.json`)에만 쓰며 `data/artifacts.js`를 쓰려 하면 거부한다.
검토 파일에는 후보, 제외 항목과 이유, 실패한 요청이 함께 남는다. 검토·승인 전에는 앱 데이터에 합치지 않는다.
`--help`는 네트워크 요청 없이 옵션을 보여 주고, `--dry-run`은 파일을 쓰지 않는다.

| 출처 | 조회 방식 | 연대·위치 근거 |
| --- | --- | --- |
| 국립중앙박물관 | 공식 검색 `백자`, `백자 청화` + 상세 페이지 | 상세의 `국적/시대` 칸만 사용. 대부분 `조선`뿐이라 `dateBasis: dynasty`(1392–1897). 위치는 광주 관요 일대 추정 |
| 고궁박물원 | 도자 소장품 검색(`/searchs/ceramics.html`) `青花`, `甜白`, `白釉` | 목록의 시대 칸. 연호(예: 明永乐)가 있으면 재위 연도로 `object-record`, 왕조만 있으면 `dynasty`. 가마 칸에 景德镇窑가 있으면 위치 `known` |
| V&A | 공식 API v2, 장소 ID(한국 `x30965`, 중국 `x29398`) | 소장품 기록의 제작 연대(`productionDates`)로 `object-record`. 제작지가 Jingdezhen이면 위치 `known` |
| The Met | 공식 Open Access API, `isPublicDomain`만 | 기록의 `objectBeginDate`–`objectEndDate`로 `object-record`. 일부 네트워크에서 자동 요청이 차단됨 |

유약 분류는 기록 자체의 제목·재질 문구로만 한다. 철화·진사·채색 등이 섞인 기물과 청백자(青白釉)는 `null`로 보고 제외한다.
조각·사진·복제품·지석(묘지석), 1368년 이전·1911년 이후 제작품도 제외한다. 2026-10-27 시험 실행(그룹당 5점)에서 V&A 한국 백자는 조건에 맞는 것이 3점뿐이었다.

## 수집기 범위와 위험

수집기는 `scripts/collect-official-artifacts.mjs`이며 자동 실행용 백엔드가 아니다.
한국은 `청자` 검색의 처음 최대 2,400항목 범위(12개씩)를 후보로 삼는다.
빈 페이지·반복 페이지면 더 일찍 끝나며 고려·청자 조건 등으로 다시 거른다.
다른 세기만 명시된 항목과 유리건판·사진자료 등의 표식을 제외한다.
중국은 고궁박물원 600주년 기획 목록의 북송·남송·송 필터 3개만 읽는다.
중국 개별 상세 전체를 순회하지 않으며 박물관 전체 검색을 망라하지 않는다.
제목·시대·재질·분류는 HTML 정규식과 문자열 규칙으로 추출해 오인식 가능성이 있다.

한국 상세 조회는 작업자 4개, 각 요청은 최초 포함 최대 4회 시도한다.
재시도 간 대기는 있지만 명시적 요청 시간 제한, 캐시, 중단 후 재개는 없다.
출력 경로 옵션·미리보기 모드는 없고 최종 결과로 `data/artifacts.js`를 덮어쓴다.
개별 한국 상세 요청 실패는 경고 후 건너뛰며 전체 건수 감소로 이어질 수 있다.
양국 결과가 비어 있는지는 검사하지만 부분 누락을 자동으로 막지는 않는다.
목록 요청 실패는 전체 실행을 중단할 수 있으며 병렬 완료 순서로 배열 순서가 달라질 수 있다.
재수집은 수동 보정도 지울 수 있으므로 별도 승인·백업·차이 검토가 선행되어야 한다.

## 과거 이력과 새 검증

인수인계 기록에는 `outveiw-tit` 제목 처리 정규식 수정과 제목 10건 수동 보정이 있다.
현재 소스의 해당 오타 대응은 확인했으나 과거 10건을 원문과 새로 대조하지는 않았다.
새로 확인한 것은 위 집계와 로컬 구현이며 수집기·원격 URL은 실행·조회하지 않았다.
`node scripts/check.mjs` 같은 오프라인 검사와 CI 통과는 데이터 형식의 검증이다.
개별 연대·지리·소장 이력·이미지 이용 권한에 대한 학술적·권리상 증명은 아니다.
