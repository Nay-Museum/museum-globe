# 구조와 실행 경계

## 현재 형태

Museum Globe는 한국·중국 유물을 세기별로 비교하는 정적 프로토타입이다.
HTML, CSS, 일반 JavaScript로 구성하며 빌드, npm 설치, 백엔드, 인증, 환경변수는 없다.
브라우저 실행에는 HTTP로 제공되는 정적 파일과 WebGL 지원이 필요하다.
Python HTTP 서버는 개발용 파일 서버이며 애플리케이션 API 서버가 아니다.
Node.js는 수집·검증 도구에만 사용하며 사이트 실행 의존성이 아니다.
오프라인 검사는 Node.js 22 이상이 필요하며 CI도 Node.js 22를 사용하도록 설정되어 있다.
독립 저장소의 사이트 루트는 `index.html`이 있는 `.`이며 `docs/`는 배포 루트가 아니다.

## 파일별 책임

| 경로 | 책임 |
| --- | --- |
| `index.html` | 화면 구조, 컨트롤, 순서가 있는 스크립트 로드 |

| `vendor/globe.gl.min.js` | Globe.gl 2.46.1 번들, Three.js 기반 렌더링 포함 |

| `data/museums.js` | `window.MUSEUMS`에 소장처 메타데이터 제공 |

| `scripts/collect-official-artifacts.mjs` | 공식 사이트에서 스냅샷을 갱신하는 별도 도구 |

## 로드와 데이터 흐름

`index.html`은 다음 순서로 일반 스크립트를 동기 로드한다.

1. Globe.gl 번들이 전역 `Globe`를 등록한다.
2. 텍스처, 박물관, 시대, 유물 파일이 각각 `window` 전역을 등록한다.
3. `js/app.js`의 즉시 실행 함수(IIFE)가 데이터를 읽고 이벤트를 연결한다.
4. 초기 `render()`가 12세기, 한국·중국, 전체 분류 상태를 표시한다.

ES 모듈, 번들러, 라우터, 데이터베이스, 서버 측 검색은 사용하지 않는다.
유물과 박물관 목록은 시작 시 참조하며 박물관은 ID 기반 `Map`으로 변환한다.
세션 상태는 메모리에만 있고 새로고침하면 초기화된다.
유물 메타데이터를 가져오는 런타임 API 호출도 없다.
사진은 각 레코드의 원격 이미지 URL을 브라우저가 직접 요청한다.

## 상태와 필터

`state`는 `century`, `cultures`, `category`, `search`, `selectedId`를 보관한다.
문화권은 `KR`·`CN` 집합이며 버튼 조작으로 적어도 하나는 남긴다.
분류는 전체 또는 `metalcraft`·`ceramic`·`painting`이다.
검색은 이름, 한자명, 재질, 연대 표제, 왕조명·한자, 위치 설명의 부분 일치다.
박물관 이름과 설명문 전체를 검색하는 기능은 현재 없다.

선택 세기의 범위는 `(세기 - 1) * 100 + 1`부터 `세기 * 100`까지다.
유물의 `yearStart`~`yearEnd`와 이 범위가 겹치면 포함한다.
슬라이더는 5~19세기지만 현재 스냅샷은 모두 12세기에만 겹친다.
눈금은 현재 문화권·분류·검색을 반영하되 세기 조건은 제외해 계산한다.
이전·다음 버튼은 필터와 무관한 전체 데이터의 세기 목록을 순환한다.
따라서 필터 결과가 없는 세기로도 이동할 수 있다.

## 지도 좌표와 선택

`origin.certainty !== "unknown"`이고 위도·경도가 유한한 숫자이면 지도에 올린다.
`unknown`은 별도 목록에 배치하며 좌표는 `null`이어야 한다.
현재 1,125건은 모두 `capital-fallback`이며 확정 출토지·제작지가 아니다.
소장처의 서울·베이징 좌표는 유물 위치의 근거로 사용하지 않는다.

`buildPointCoordinates()`는 문화권·소장처·소수점 셋째 자리 좌표로 묶는다.
같은 위치의 유물을 황금각 나선으로 펼쳐 점의 겹침을 줄인다.
집단 크기에 따라 최대 반경 1.2·2.4·3.8의 각도 기반 오프셋을 적용한다.
이 값은 거리 단위나 조사 결과가 아니라 화면 표시용 설정이다.
원본 `origin`을 바꾸지는 않지만 클릭 시 카메라도 이 표시 좌표로 이동한다.
**점의 분포나 밀도를 실제 유물 분포, 교류 경로, 생산지 증거로 해석하면 안 된다.**

마커 또는 목록 클릭은 `selectedId`를 바꾸고 전체 화면을 다시 렌더링한다.
필터에서 선택 유물이 사라지면 상세와 팝오버를 비운다.
팝오버 닫기는 선택을 해제하며 자동 회전은 별도 체크박스로 제어한다.
회전·줌·드래그는 Globe.gl의 Three.js 컨트롤에 의존한다.
카메라·컨트롤 상태 일부는 점검용 `data-*` 속성에 복사한다.

## 렌더링과 알려진 제약

목록·상세·팝오버·점 툴팁은 데이터 값을 HTML 문자열로 삽입한다.
데이터 전체에 대한 이스케이프와 URL 검증은 아직 구현되어 있지 않다.
검색어 자체를 HTML에 넣지는 않지만 수집된 제목·설명·URL도 신뢰 경계 밖이다.
공개 입력이나 새로운 수집 소스를 연결하기 전에 모든 삽입 지점을 점검해야 한다.
현재 사진 오류 대체 화면과 WebGL 실패 전용 화면도 없다.
매 입력마다 목록과 상세를 재생성하므로 대용량 목록 성능은 별도 과제다.

데스크톱은 지구본과 390px 측면 패널을 나란히 배치한다.
980px 이하에서는 세로 배치, 560px 이하에서는 비교 목록 등을 한 열로 바꾼다.
CSS에 분기점이 있다는 사실이 실제 모바일 조작 검증을 대신하지는 않는다.

## 실행과 자산 보존

저장소 루트 `.`에서 `python3 -m http.server 4173 --bind 127.0.0.1`로 정적 파일을 제공한다.
`file://` 직접 실행 대신 HTTP 주소를 사용하고 사용 중인 포트는 변경한다.
지도는 `img/earth-blue-marble.jpg`를 읽지만 현재 유물 사진은 전부 원격 URL이다.
원격 사진에는 네트워크, 주소 변경, 외부 연결 제한의 영향을 받는 경계가 있다.
나머지 과거 `img/` 유물 파일은 현재 데이터에서 참조하지 않는 스냅샷이다.
미사용이라는 이유로 삭제하지 않으며 권리 확인된 현재 사진이라고 간주하지도 않는다.
수집기는 브라우저와 분리되어 있고 실행하면 `data/artifacts.js`를 덮어쓴다.
일반 실행·테스트·문서 수정에 수집기를 호출할 필요는 없다.

## 검증의 경계

이번 문서 작성에서는 실제 소스와 로컬 데이터 집계를 확인했다.
`node scripts/check.mjs`는 로컬 Node.js 25.6.0에서 통과했다. CI 실행 결과를 확인한 것은 아니다.
수집 재실행, 원문 URL 재조회, 브라우저·배포 화면의 신규 검증은 하지 않았다.
인수인계된 과거 화면 확인 이력은 당시 상태의 기록이지 이번 통과 결과가 아니다.
오프라인 검사와 CI는 구문·데이터 규칙을 점검하며 학술적 사실을 입증하지 않는다.
명령과 구현된 검사 범위는 루트 README와 검사 스크립트를 함께 확인한다.
연대·위치·소장처·권리의 의미와 한계는 [DATA.md](DATA.md)를 따른다.
개선 순서와 완료 기준은 [ROADMAP.md](ROADMAP.md)에 분리한다.
